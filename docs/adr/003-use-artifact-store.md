# ADR 003: Хранение артефактов (локальная ФС для MVP, S3 для продакшена)

- **Статус:** Принято
- **Дата:** 2026‑01‑08
- **Обновлено:** 2026‑01‑08

## Контекст

В процессе обработки образуются различные файлы: исходное видео, нормализованное видео, ключевые точки, фичи, фидбек и потенциально другие промежуточные результаты (визуализации, heatmap'ы). Эти файлы могут иметь большой объём и должны быть доступны как воркерам, так и фронтенду. База данных не предназначена для хранения больших бинарных объектов. Требуется решить, где хранить артефакты и как к ним обращаться.

## Решение

Для MVP на личном ПК используется **локальная файловая система**. Система спроектирована с абстракцией storage backend, что позволяет легко переключиться на Object Storage (MinIO/S3) при масштабировании.

### Рекомендация для MVP: Локальная файловая система

Для MVP на одном ПК локальная ФС является оптимальным выбором:

1. **Простота развёртывания.** Не требуется запускать MinIO или другие дополнительные сервисы. Меньше компонентов для мониторинга и поддержки.
2. **Производительность.** Прямой доступ к файлам без сетевой задержки. Воркеры читают и пишут файлы напрямую с диска.
3. **Меньше ресурсов.** Не нужен отдельный контейнер для MinIO, экономия памяти и CPU.
4. **Достаточно для одного ПК.** Для MVP на личном компьютере нет необходимости в распределённом хранилище.

### Архитектура: Абстракция Storage Backend

Система использует абстрактный интерфейс `StorageBackend`, который поддерживает два варианта:

- **LocalStorageBackend** — для локальной ФС (рекомендуется для MVP)
- **S3StorageBackend** — для Object Storage (MinIO/S3) при масштабировании

Переключение между backends выполняется через конфигурацию (`STORAGE_BACKEND=local` или `STORAGE_BACKEND=s3`).

### Структура хранения (локальная ФС)

```
runtime/storage/
  raw/              # Оригинальные видео
    {video_id}/
      original.mp4
  proc/             # Обработанные артефакты
    {video_id}/
      normalized.mp4
      keypoints_v1.jsonl
      features_v1.json
      feedback_v1.json
```

### Доступ к файлам (локальная ФС)

Для локальной ФС используется прямой доступ через API endpoints:
- Загрузка: `POST /v1/videos` → возвращает endpoint для загрузки через API
- Скачивание: `GET /v1/videos/{id}/artifacts` → возвращает прямые пути `/files/{video_id}/{artifact}`

## Альтернативы рассмотрены

- **Object Storage (MinIO/S3).** Оптимально для продакшена и масштабирования. Обеспечивает высокую доступность, репликацию, presigned URLs. Требует дополнительный сервис (MinIO) или облачный S3. Рекомендуется при переходе к продакшену или при необходимости масштабирования.
- **Хранение в БД (BLOB).** База данных затрудняет работу с большими файлами: влияет на размер бэкапов, производительность запросов и сложность масштабирования. Это упрощает транзакционные свойства, но не подходит для гигабайтных видео.
- **Content Delivery Network (CDN).** CDN может применяться для раздачи результатов пользователям, но для записи и внутреннего хранения всё равно нужен origin‑storage.

## Последствия

### Локальная ФС (MVP)

- **Плюсы:** Простота развёртывания, высокая производительность (нет сетевой задержки), меньше ресурсов, достаточно для одного ПК.
- **Минусы:** Не масштабируется на несколько нод, нет репликации, данные привязаны к одному ПК.

### Object Storage (Продакшен)

- **Плюсы:** Высокая доступность, гибкие механизмы безопасности (IAM, presigned URL), простота интеграции с облачными провайдерами, масштабируемость.
- **Минусы:** Обработка файлов требует сетевого доступа (задержка). Для локальной разработки нужен локальный S3‑совместимый сервер (MinIO). Следует контролировать TTL presigned URL и очищать старые артефакты.

## Миграция в будущем

Когда понадобится масштабирование или переход в продакшен:

1. Изменить `STORAGE_BACKEND=s3` в конфигурации
2. Запустить MinIO или подключить облачный S3
3. Код остаётся без изменений благодаря абстракции

Итог: для MVP на личном ПК локальная файловая система является оптимальным выбором. Абстракция storage backend позволяет легко переключиться на Object Storage при росте требований. База данных остаётся местом хранения метаданных и ссылок на файлы.
